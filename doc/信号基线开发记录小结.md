## 4.1 2026-10-26 上机失败修复（重要）

### 现象
1 kHz / ~3 V 峰值高斯脉冲接 CH1、CH3：点 start analyze 后这两路 `baseline_valid` 恒为 No，未接通道恒为 Yes；stop analyze 后又变回 Yes。ILA 中 `sample_valid` 正常、`state` 长期钉在 0（ACQUIRE）。基线值仍显示 ~40000 量级（看似合理，实则是脉冲串均值）。

### 根因
`max_pulse_wid` 的单位是**采样点**，复位默认 255。系统 ~1 MSPS，255 点只有 **0.255 ms**，比一个 1 kHz 高斯脉冲「高于阈值的那一段」还短。于是**每个真实脉冲都会触发一次看门狗**：

- 旧实现里看门狗会把 FSM 退回 `S_ACQUIRE` 并清 `baseline_valid`；
- `wid_cnt` 在 ACQUIRE 期间也在计数、切状态不清零，所以 ACQUIRE 跑完进入 TRACK 的第一拍就可能带着饱和计数再次触发；
- 触发后 `baseline_valid=0`，`detect_ref` 退回**绝对阈值**，而阈值语义已改为「峰高」，与实际电平不匹配 → 脉冲占空更大 → 更早触发 → **自锁**。

结果估计器 >95 % 时间停在 ACQUIRE（快 EMA，α=2⁻⁴），`baseline_valid` 只亮 1 拍/1024 拍，且基线收敛到**脉冲串均值**而不是底噪。

### 修复
| 文件 | 改动 |
|---|---|
| `baseline_estimator.v` | 看门狗只在 `S_TRACK` 计数、切换清零，且**只置 `overflow` 状态位，不再改变状态机、不再清 `baseline_valid`**；**取消自动重收敛（rescue）**：超宽脉冲只冻结基线，需要重收敛时由操作者/上位机显式发 `acquire_force` |
| `signal_analyzer_v1_0_S00_AXI.v` | `pulse_analyzer.enabled` 增加 `& (~baseline_en \| baseline_valid[i])`：基线未收敛时不检测脉冲，从根上断掉自锁；`slv_reg4` 复位默认 255 → **4095**；`slv_reg44[9]` 输出 `overflow` |
| `signal_analyzer.c` | `baseline_reacquire()` 把 `acquire_force` 保持 ~2000 次空转（约几 μs）；新增 `read_control_reg/_baseline_ctrl_reg/_baseline_param_reg/_baseline_param2_reg` |
| `cytometer.c` | `cytometer_start_analyze/stop_analyze` 改为**幂等**（不再因 `current_state != STATE_IDLE` 静默丢弃，避免 PL 重下载后 `analyze_en` 卡在 0）；START 时重新下发缓存的阈值/使能通道；新增 `cytometer_read_pl_config()` |
| `udp_server.c` | `CMD_BASELINE_MONITOR` 回帧由 36 字节扩到 **52 字节**，尾部追加 `slv_reg0/2/3/4` 回读 |
| 上位机 | `BaselineDebugDialog` 新增「PL readback」一行并高亮与输入框不一致的项；`Max Pulse Width` 默认值 255 → 4095 |

### 行为变化（联调须知）

- 超宽脉冲只**冻结基线 + 置 overflow 标志**，**不做任何自动重收敛**。若输入电平真的跳变（换增益/放片子/开 LED），基线会停在旧值，需要点 **Re-acquire**（或由上位机按策略下发 `acquire_force`）。这是有意取舍：v2 的自动 rescue 在检测参考出错时会把基线拉到脉冲均值，实测跳变幅度 ~56 k 码、周期 = 4×max_pulse_wid + acquire_len —— 把 max_pulse_wid 调大只会让跳变更慢，不会更小。
- 基线校正打开时，`baseline_valid=0` 期间**不产生脉冲/事件**（约 1 ms 的首收敛窗口）。
- `max_pulse_wid` 必须大于最宽真实脉宽，但它现在**只影响告警，不影响基线行为**。
- 只读状态位：`slv_reg44[9]` = 任一通道 overflow，`slv_reg44[11]` = 监控通道状态（1=TRACK）。
- **`threshold`（slv_reg8..15）为 0 时，`detect_ref` 塌到基线本身** → 任何高于基线的采样都被判成脉冲 → `pulse_active` 常驻 → `Pulse Width` 必然超限 → overflow 常亮。这不是基线的问题，是检测阈值没下发。上位机监视表已加 `Threshold` 列，为 0 会标红。

### 2026-10-27 修复：两处定点溢出（大范围跳动的真正根因）

上板复测的两个读数指向同一类问题 —— **定点加法没有饱和**：

| 现象 | 机理 | 修复 |
|---|---|---|
| CH1 基线 130027、阈值 3000 ⇒ `detect_ref = 133027`，超过 18 位有符号上限 131071，**回绕成 -129117** ⇒ 每拍都"高于阈值"⇒ `pulse_active` 常驻 ⇒ 无论 `max_pulse_wid` 多大都报 overflow | `pulse_analyzer.v` 里 `baseline_out + threshold_value` 是无饱和 18 位加法 | 改为**饱和加**（正溢出→+FS，负溢出→−FS） |
| 基线在 +131000 与 −131000 之间来回大跳 | `baseline` 是 Q18.6 的 **24 位**，整数部分上限 **+131071.98**。输入削顶时基线停在 +FS，再向上一步就**回绕成 −131072**，之后慢慢爬回轨再绕一次 | `baseline_estimator.v` 的 `next_baseline` 无饱和 | 改为**饱和加**（同上） |

附带：`threshold <= 0` 的通道**关闭脉冲检测**（`pulse_analyzer.v` 的 `threshold_usable`）。阈值 0 意味着"高于基线即脉冲"，在没有检测器设置时会用噪声造出脉冲，进而门控掉基线的 TRACK 更新。

> 注意：如果输入电平本身已经顶到 ADC 满量程（基线 ≈ +131000），即使溢出修好，基线也只能停在轨上 —— 那是**前级增益/量程**问题，需要先把信号幅度降下来。

### 2026-10-27 修复：`gate_judge_pipeline.v` 时序违例

实现报告（`impl_1/runme.log`）显示 **设计未满足时序**：

```
CRITICAL WARNING: [Timing 38-282] The design failed to meet the timing requirements.
WNS = -0.621 ns   TNS = -1.095 ns   10 个失败端点
```

10 个失败端点全部落在 `gate_wrapper/u_gate_judge`，即本模块的两条"乘加+比较挤在一拍"的链路：

| 链路 | 原路径 | 拆分方式 |
|---|---|---|
| 多边形 | `s1_c`(32b) → DSP 32×32 乘 → **64 位有符号比较** → XOR → `crossing_acc`（14 级逻辑，5.445 ns） | 乘法结果先寄存进 `s2_lhs/rhs`（新增 S2 级），比较+XOR 放到下一级（S3） |
| 椭圆 | `ell_t1 + ell_t2`（**132 位加**）与 `<= ell_rhs`（**132 位比较**）同一级 | 加法寄存进 `ell_sum`（新增 S4 级），比较放到下一级（S5）；`ell_rhs` 同步打一拍（`ell_rhs_d`）对齐 |

**代价**：多边形延迟 `N+2 → N+3`、椭圆 `5 → 6` 拍（状态机里 `ell_cnt` 的判据由 4 改为 5）。吞吐不变——每拍仍接收一条边，每次触发仍只出一个 `valid` 脉冲；下游 `hierarchical_gate_wrapper` 在 `ST_COMPUTE` 里按 `gate_valid` 握手，所以这点延迟是透明的。

> 重综合后请确认 `report_timing_summary` 的 WNS ≥ 0；若仍有违例，把最差 3 条路径发出来再继续收敛。

### 诊断手段（2026-10-26 追加）
- `slv_reg44[31:24] = 0xA7` 是**构建标识**。上位机 Baseline Debug Console 会直接显示「PL: 2026-10-26 版」或「⚠ PL 是旧版本」——**旧 .bit 没重新下载 / IP 没重新打包时，任何代码修改都会看起来完全无效**，这一条用于先把这种情况排除掉。
- `slv_reg55 @ 0xDC`：`[15:0]` = ADC 采样边沿自由计数，`[31:16]` = 监控通道的 ACQUIRE 进度。连续两次 Refresh 比较：
  - `sample_cnt` 不变 → ADC / `ad_data_valid` 通路已停，估计器永远走不完 ACQUIRE（表现为 `valid` 恒 0、基线值冻结在出问题那一刻）；
  - `sample_cnt` 在涨而 `acq_cnt` 不动 → FSM 被卡住；
  - `acq_cnt` 在涨 → 只是在等 1024 个采样。
- 上位机同时把 `slv_reg0/2/3/4` 与输入框逐字段比对，不一致直接标红（用于识别 Apply 没落地）。

## 6. ⚠️ 阈值语义变化（重要，联调必看）

`slv_reg8~15` 的阈值含义已从「绝对 ADC 码值」变为「相对基线的峰高」：

- 触发参考（`baseline_valid=1` 时）= `baseline_out + threshold`，等价于 `(sample - baseline) > threshold`
- `baseline_valid=0`（ACQUIRE 阶段，启动后约 1ms）仍按绝对阈值
- 上位机阈值需按「峰高」重新标定；沿用旧的绝对码值（如 10100）会被当成峰高，导致漏触发

## 8. 待办与已知缺口

1. **`acquire_force` 语义**：文档原设想 W1C，实际为普通 R/W；PS 用「置 1 再清 0」产生一次重收敛脉冲
2. **上位机命令映射**：UDP 命令 → `write_baseline_settings` / `write_baseline_params` / `read_baseline_mon` 未接（阶段4）
3. **`sample_baselined` 悬空**：`baseline_estimator` 已输出该信号但未接线（阶段2 走 `detect_ref` 方案，未用逐样本减）；留待阶段2 验证后决定是否切逐样本减
4. **RTL 未综合验证**：环境无 iverilog/verilator，需在 Vivado 综合确认（重点：`detect_ref` 符号位宽、`baseline_out+threshold_value` 不溢出——按基线 ≤10000 定标余量充足）
5. **面积修正资源**：`area - baseline*width` 每通道新增 1 个 DSP 乘法器，与设计方案「DSP 增量 0」目标不符（需确认可接受或改逐样本减）

## 附：基线估计器关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `C_AD_DATA_DEPTH` | 18 | 采样位宽 |
| `C_FRAC_BITS` | 6 | 基线小数位（Q18.6，内部 24bit） |
| `acquire_len` | 1024 | 预热样本数：数满后 `baseline_valid` 才置 1 |
| `alpha_shift` | **16** | **慢升档** α=2^-16（sample 高于估计时用） |
| `max_pulse_wid` | **4095** | **电平跟随时限**：连续这么多采样无低于基线的样本 → 慢升腿临时提速到 2^-6（0=关闭）。必须明显大于一个脉冲周期的采样点数 |
| （固定） | 4 | **快降档** α=2^-4（sample 低于估计时用）——这是基线能贴住包络底、且不追脉冲的关键 |
| （固定） | 2048 码 | 单拍步进钳位，限制单颗离群采样的破坏 |
| `guard_len` / `slope_th` / `pulse_active` | — | **不再使用**（极简实现不需要；寄存器位保留以兼容旧上位机） |

> 现场实测（1 kHz、3 V 峰值高斯脉冲，0 V 低电平）：`alpha=14` 时基线在 **1200~1900** 摆动，`alpha=16` 时收窄到 **1200~1400**，散点与事件均正常。上电后基线需要几秒爬到稳定值（慢升腿所致），属正常。

## 附：面向用户的使用方式（2026-10-28 整合）

基线功能已从"工程师调试窗口"移到用户的常规流程：

**参数入口**：主窗口「Cytometer」面板 → `Baseline` 分组（与检测器增益/阈值同一个 dock）。

| 控件 | 含义 | 默认 |
|---|---|---|
| `Enable baseline correction` | 总开关。打开后阈值表示「高出基线的峰高」而非绝对码值 | 关 |
| `Response (alpha)` | 慢升档 2^-n，越大越稳 | 16 |
| `Max Pulse Width` | 电平跟随时限（采样点，0=关闭） | 4095 |

- 参数改动**即时下发并落库**（无 Apply 按钮），表 `baseline_settings`（整机单行）。
- Zynq 重新连接、以及 PS 的每次 START，都会自动重下发（PL 重下载 bitstream 后不会丢配置）。
- 分组底部实时显示**使能通道**的当前基线（1 Hz 轮询，帧 36 字节）。

**观察入口**：
1. 波形图上的**虚线基线参考线**（每通道一条，颜色同曲线，`Baseline` 复选框控制）——
   基线应当贴住信号底部；若与波形底部明显分离，说明需要重新采集基线。
2. 设置分组底部的数值行（`CH1 1302   CH3 1381`）。

**售后排查**：`Engineer` 菜单（仅管理员）里的 `Baseline Debug Console` 保留，可看 8 通道全部
基线与区间，并手动 Re-acquire。

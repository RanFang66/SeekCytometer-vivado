# 信号基线功能 Debug 复盘（2026-10-26 ~ 10-27）

- 分支：`refactor/baseline`（Vivado / Vitis / Qt 三个仓库各一）
- 涉及模块：`signal_analyzer` IP（`baseline_estimator` / `pulse_analyzer` / `gate_judge_pipeline` / `S00_AXI`）、PS `udp_server.c`、上位机 `BaselineDebugDialog`
- 结论：**根因是一行 Verilog 移位语句的符号语义**。为此花了约 10 轮上板验证，其中前 7 轮都在修补下游症状。

---

## 一、最终根因（一页看懂）

### 出错代码

```verilog
// baseline_estimator.v（旧版）
wire signed [24:0] next_baseline_raw =
    {baseline[23], baseline} + (err_reg >>> ema_shift);
```

### 实际行为

`err_reg` 为 **负数**（采样低于当前估计）时，`err_reg >>> k` 表现为**逻辑右移**：最高位补 0，一个 −29770 的误差变成 +2^24 量级的正数，于是基线被**向上**推一大步。

### 机理链

```
负误差 → 被当成巨大正数 → 基线每拍向上跳 |err|/2^k
      → 基线爬到 +FS（131071，Q18.6 定点上限）
      → 饱和钳位把它钉住（或配套的补救机制把它重播种）
      → 表现的形态取决于当时又加了哪些"补救机制"
```

### 修法：符号-幅值分离，让移位永远作用在非负数上

```verilog
wire [24:0] err_mag  = err_reg[24] ? (~err_reg + 1'b1) : err_reg;
wire [24:0] corr_mag = err_mag >> cur_shift;              // 幅值右移，逻辑/算术等价
wire signed [24:0] corr = err_reg[24] ? -$signed(corr_mag) : $signed(corr_mag);
```

### 验证

- ILA 同屏：`err_reg` = 负值，`baseline` 却在上升，且每步 ≈ |err|/2^k —— 唯一可能是逻辑右移。
- 修后重建：`err_reg` 负 → `baseline` 正常下降；CH1/CH3 收敛到真实底噪。

> **关于标准**：按 IEEE 1364/1800，`>>>` 左操作数为 signed 时应做算术右移，而 `err_reg` 已声明为 `reg signed`。实测行为与标准不符（可能是工具在 `unsigned_concat + (…)` 这种混合上下文中对操作数做了无符号推导）。无论归因如何，工程结论只有一条：**不要依赖隐式符号推导，显式写出符号意图**。

## 二、故障时间线（10 轮）

| 轮次 | 现象 | 当时的假设 | 用什么验证 | 结论 |
|---|---|---|---|---|
| 1 | baseline 大范围跳动，偶尔出现正确值 ~42000；点 enable 后 valid 恒 No | 看门狗死锁：`valid=0` 时 `detect_ref` 退回绝对阈值 → 脉冲常驻 → 进 TRACK 即被踢回 | 写位精确 Python 模型复现 | 机理成立，但**不是本次现象**（当时 PL 是旧镜像） |
| 2 | 实测 `analyze_en=0`、`pulse_active=--`、调 `max_pulse_wid` 无效 | 撤回死锁论；怀疑 PS/PL 状态不同步或旧 bitstream；也怀疑过 AXI 回读缺内存屏障 | 查 BSP `translation_table.S`，PL 区是 Strongly Ordered | 屏障论**证伪并撤回**；锁定"镜像可能不是最新" |
| 3 | start analyze 后 `Analyze Enable` 仍显示 No；`state` 定死；CH1/CH3 一开采集就 No、停采集就 Yes | `max_pulse_wid=255` 只有 0.255 ms @1 MSPS，比 1 kHz 高斯脉宽还短 → 每个脉冲都触发看门狗 | 模型跑 1 kHz 脉冲串，不同采样率扫描 | **成立**。修：看门狗只在 TRACK 计数、不作废 valid、`max_pulse_wid` 默认 4095、`enabled` 门控、START 幂等、寄存器回读 |

| 5 | 8 路 valid 全 No；CH1 基线 130027、阈值 3000；`reg3=0xFF080400`、`reg4=0` | 一度认为"输入削顶、前级过载" | 用寄存器复位值指纹比对 git 历史 | **判断错误**。真正原因是**板上跑的是 10-23 之前的旧 bitstream**（`reg3` 复位值 `0xFF080400` 是旧版特征）。加构建标识 `0xA7` 后才确认 |
| 5b | （同轮）基线稳定停在 131071 | — | 静态分析 | `detect_ref = 130027 + 3000 = 133027` 超过 18 位上限 131071，**回绕成 −129117** → 判决"永远在脉冲中"。修：饱和加 |

| 7 | 同上，且 `Re-acquire` 完全拉不动基线 | 换成"数学上有界"的极简实现，并请对方抓 ILA 内部状态 | 重写 `baseline_estimator`（凸组合 IIR） | 缩小了怀疑面 |
| 8 | ILA 同屏：`baseline` 每 4 拍 `42k→70k→103k→131071`，`err_reg` 为负，每步 ≈ \|err\|/4 | 移位语义错误 | ILA + 模型复现"逻辑右移" | **根因确认** |
| 9 | 修后 CH1/CH3 到 1266/1342、TRACK x8、散点前仍无事件 | — | 寄存器回读 | 主体修复成功 |
| 10 | 仍报"跳到 70000 多" | 但 `Swing` 只有 782，逻辑上不可能收到过 40000 | 对照截图里 `Sample` 列 | **观察误差**：跳的是 `Sample`（瞬时采样），基线一直是 1302 |

## 三、为什么这个 bug 能伪装成 6 种不同故障

同一行错误，因为周围不断增删"补救机制"，在每一轮呈现不同的外形：

| 表象 | 当时的"补救机制" | 同一根因的实际行为 |
|---|---|---|
| valid 恒 No、state 卡在 ACQUIRE | `valid=0` 时退回绝对阈值 | 基线爬满量程 → 判决恒为脉冲 → `in_baseline` 恒假 → 冻结 |
| 基线稳定停在 131071 | 24 位定点饱和钳位 | 爬到上限后不再下降，被钳位钉住 |
| 基线每 4 拍锯齿跳变（≈ 88000 码） | `recover_seed`：触顶就用当前采样重播种 | 冲到上限 → 重播种 → 再冲 → 形成锯齿 |
| `acq_cnt` 永远是 1 | 重播种时 `acq_cnt<=0` | 状态机永远走不出 ACQUIRE |
| `Re-acquire` 完全无效 | `acquire_force` 只把状态切回 ACQUIRE | ACQUIRE 的更新同样被符号 bug 反转 → 看不出变化 |
| `detect_ref` 判决异常 | `threshold=0` 时参考塌到基线 | 参考值被爬满量程的基线带到溢出 |

**教训：每加一层"补救机制"，都在为同一个根因制造一个新的假象。** 症状修补会显著提高后续定位成本。

## 四、有效的诊断手段（按性价比排序）

| 手段 | 本次贡献 | 说明 |
|---|---|---|
| **ILA 同屏看内部状态** | ★★★★★ | 决定性。`err_reg`（负）与 `baseline`（上升）同屏一问就破。此前 7 轮都在看"输出"和"寄存器回读" |
| **构建标识（0xA7）** | ★★★★★ | 一眼识别"板上不是最新镜像"，避免了在旧 bitstream 上持续误判 |
| **寄存器回读面板** | ★★★★☆ | `reg0/2/3/4` + `Sample/Threshold/acq_cnt/state` 排除了大量"下发没落地""采样不在预期"的怀疑 |
| **位精确模型** | ★★★☆☆ | 能快速证伪/证实机理（看门狗、rescue、逻辑右移都复现成功），但**输入是假设的**，从未直接找到根因 |
| **静态分析 / 读代码** | ★★☆☆☆ | 本轮多次给出"按代码必须成立"的结论，却被实测推翻 —— 代码正确 ≠ 网表行为正确 |
| **用户观测的单点读数** | ★☆☆☆☆ | "130027 稳定""跳到 70000" 都是观测口径问题，误导了两轮 |

## 五、走过的弯路（反面清单）

1. **把"代码应该怎样"当成"硬件实际怎样"。** 多次以"ACQUIRE 里是无条件更新，所以基线必须会动"为由排除估计器，最终恰恰是估计器内部语义错了。
2. **只看输出、不看内部。** 前 7 轮盯的是 `baseline`/`valid`/`state`（都是输出），直到看 `err_reg` 才破局。
3. **反复修补下游症状。** 依次加了：看门狗 → rescue → 发散守卫 → 逻辑右移掩码意义上的钳位。每一层都制造新现象，把时间线拉长了数轮。
4. **在信息不足时用模型"证明"结论。** 模型的信号（采样率、底噪、占空比）都是我猜的，结论却当成了事实。
5. **没有第一时间确认镜像版本。** 第 5 轮才发现板上跑的是 10-23 的旧 bitstream，此前所有"改完没效果"都掺了这个因素。
6. **把用户的一次读数当作稳态。** "基线稳定在 130027"其实是跳动序列里的一个采样点；"跳到 70000"其实是邻列的瞬时采样值。**单点读数不构成证据，min/max 才算。**
7. **判断失误时没有立刻缩小假设空间。** 例如"输入削顶"论，仅凭基线接近满量程就下结论，没有先看 `Sample` 列。

## 六、已落地的工程改进

### PL

| 改动 | 作用 |
|---|---|
| `slv_reg44[31:24] = 0xA7` 构建标识 | 区分镜像新旧 |
| `slv_reg44[17:10]` 8 通道状态位 | 一眼看出 ACQUIRE/TRACK 分布 |
| `slv_reg55 @ 0x37`：`[31:14]` 原始采样、`[13:0]` 采样节拍 ÷256 | 判断"ADC 有没有在转、转得多快" |
| `0x3F`：ACQUIRE 进度计数 | 判断状态机有没有在走 |
| `pulse_analyzer`：`detect_ref` 饱和加；`threshold<=0` 关闭检测 | 消除 18 位回绕；阈值未配置时不再用噪声造脉冲 |
| `gate_judge_pipeline`：多边形/椭圆各拆一级流水 | 修掉 WNS −0.621 ns 的时序违例 |

### PS

| 改动 | 作用 |
|---|---|
| 监视帧 36 → **124 字节** | 追加 `reg0/2/3/4`、诊断字、8 路阈值、8 路原始采样、ACQUIRE 计数 |
| `start/stop_analyze` 幂等 | 避免 PL 重下载后 `analyze_en` 卡在 0 |
| `baseline_reacquire` 保持时间 | 原来两次背靠背写，估计器可能整个漏掉 |

### 上位机

| 改动 | 作用 |
|---|---|
| `Baseline (est.)` / `Sample (inst.)` / `Baseline range` 列名 | 从命名上区分"估计值"与"瞬时采样值"，杜绝本次的误读 |
| `Threshold` 列（0 标红） | 一眼看出检测器是否配置 |
| PL 值与输入框逐字段比对（不一致标红） | 识别"Apply 没落地 / PL 被复位" |

## 七、下次的 Checklist

**上板前**
1. 确认板上镜像：看构建标识；没有构建标识就先加一个。
2. 确认时序收敛：WNS ≥ 0，`runme.log` 无 `[Timing 38-282]`。

**定位阶段**
3. 先建立"输入 → 内部状态 → 输出"三元观测，再动代码。少任何一环都会变成猜。
4. 对任何"输出不合物理规律"的现象，**优先抓内部状态**（ILA），不要先改算法。
5. 单点读数不构成证据；用 min/max、区间、长时间统计说话。
6. 一次只改一个变量；每次改完要能**证伪**（改完预期会看到什么、看不到什么）。
7. 不要用"补救机制"绕过症状。若必须加，明确写下"这是绕过，不是修复"，并在根因找到后删除。

**代码层面**
8. 禁止在同一表达式中混用有符号数与无符号拼接；所有算术右移显式写 `$signed()`，或改成"符号-幅值"形式。
9. 定点加法一律饱和，并给饱和加写一行注释说明为什么需要。
10. 估计器/滤波器类模块，输出应满足"凸组合"性质（输出落在输入范围内）；这既是数学保证，也是最强的自检。

## 八、附录

### 最终实现（`baseline_estimator.v`，约 50 行）

```
采样低于估计 → 快降 α = 2^-4     （贴住包络底）
采样高于估计 → 慢升 α = 2^-16    （不追脉冲，默认值）
单拍步进钳位 ±2048 码            （限制单颗离群采样）
预热 1024 个采样后 baseline_valid=1
```

已删除：`S_ACQUIRE/S_TRACK` 状态机、首样本播种、脉宽看门狗、`rescue`、发散守卫、`pulse_active` 门控。

### 现场实测

| `alpha_shift` | 基线区间（1 kHz / 3 V 峰值高斯，0 V 低电平） |
|---|---|
| 14 | 1200 ~ 1900 |
| **16（默认）** | **1200 ~ 1400** |
| 真实底噪 | ~1300 |
